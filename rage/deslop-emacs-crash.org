* Design (iteration 1)

** Ownership / state boundaries
- =org_vector/cli.py= owns argparse + dispatch; root =main.py= becomes a thin
  shim calling =org_vector.cli.run()= (keeps =python main.py …= and the nix
  wrapper working; fixes the setup.py entry point).
- =VectorClient= keeps its public surface: =plan_sync=, =sync_files=,
  =embed_file=, =make_document=, =query=, =remove_files=. Tests inject fake
  model/chroma via the existing =model= and =chroma_client= params — no
  network, no torch download in tests.
- Elisp keeps the same interactive command names; only internals change.

** Invariants to preserve (AGENTS.md)
1. =query= == =search=, =update= == =embed= (single =MODE_ALIASES= map now).
2. Incremental sync on (mtime_ns, size); unchanged skipped; deleted removed.
3. Re-index replaces prior chunks (delete-by-filepath then upsert).
4. Deterministic =auto-<sha1>= fallback IDs — now actually reachable.
5. Retrieval diversifies: <=1 top hit per file before backfill.

** Rejected alternatives
- Moving the CLI out of =main.py= entirely: breaks =python main.py= and the
  nix wrapper; shim keeps both.
- Making gptel query async: gptel tool functions must return values
  synchronously; async would change the tool contract. Kept sync, documented.
- Deleting =to_dataframe=: no caller in repo or CLI; pandas out of the core
  dependency path. (Recoverable from git history.)
- Auto-recreating collection on every mismatch: kept the existing guard +
  retry-on-mismatch behavior as-is (tested via fake client).

** Failure/recovery behavior
- =sync_files= logs per-file failures and continues (unchanged).
- Collection dimension mismatch during embed: reset + retry once (unchanged).
- Elisp: dead process-buffer sentinel must not error; failed CLI runs render
  the error output in the results buffer (unchanged behavior, fixed plumbing).
